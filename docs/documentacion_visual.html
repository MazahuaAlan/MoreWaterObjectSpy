MoreWater Object Spy

Captura el objeto en el instante del clic —aunque la ventana cambie o se abra un modal— y genera locators listos para Winium, rankeados por estabilidad y unicidad. Hoy para Winium; en camino, soporte para Selenium, Appium, Playwright y otras bibliotecas.

.NET 8.0 C# · WinForms UIA + MSAA + Win32 Delphi · WPF · WinForms · UWP roadmap: Selenium · Appium · Playwright by MazahuaAlan

El problema

El objeto que desaparece antes de poder leerlo

Inspect.exe, UISpy o Accessibility Insights sí encuentran los objetos. El problema aparece cuando la aplicación cambia de ventana, superpone modales o roba el foco — justo lo más común en apps de escritorio reales. El inspector pierde el objeto antes de que alcances a leer sus propiedades.

Inspector tradicional

Clic → se abre un modal → la ventana anterior cambia → el objeto original ya no está disponible. Hay que repetir e ir con cuidado.

Object Spy

Toma un snapshot inmutable en el instante exacto del clic, antes de que la app procese el evento. El objeto sobrevive aunque su ventana desaparezca.

Flujo de captura

Congelar el objeto en el instante del clic

La clave está en el orden: lo rápido y crítico ocurre síncrono dentro del hook; lo lento va después, en segundo plano.

1

Hotkey F8 instala el hook

Un hook global de mouse (WH_MOUSE_LL) queda a la escucha de cada clic en el sistema.

2

Snapshot Win32 — síncrono

En el hilo del hook, en el instante del clic (la ventana aún existe): WindowFromPoint → HWND, clase, título, PID. Datos garantizados.

3

UIA + MSAA — en segundo plano

La consulta pesada corre fuera del hook para no bloquearlo: propiedades UI Automation, ancestros y, como respaldo Delphi, MSAA.

4

Locators rankeados + resaltado

Se generan los candidatos, se verifica unicidad y se resalta el elemento en pantalla. Todo se agrega al historial.

Tres motores

UI Automation, MSAA y Win32 en paralelo

Cada motor cubre lo que el otro no ve. Juntos forman una red de seguridad, especialmente para controles Delphi que UIA a veces no expone bien.

Motor 01

UI Automation

Name, AutomationId, ControlType, FrameworkId, patterns y el árbol de la ventana.

cubre WPF · WinForms · UWP · Win32
Motor 02

MSAA

Role, State, Name, Value y DefaultAction vía IAccessible. El respaldo cuando UIA falla.

cubre Delphi / VCL · legacy
Motor 03

Win32

HWND, ClassName, título, proceso y rectángulo. El snapshot que nunca falla.

cubre cualquier ventana nativa

Inteligencia de locators

No solo muestra propiedades: recomienda el selector correcto

El generador produce varios candidatos y los ordena primero por unicidad, luego por estabilidad. Verifica en vivo cuántos elementos coinciden y, si hay varios iguales, entrega el índice determinístico sobre el atributo más selectivo.

// Objeto: Image · AutomationId="btnImage" (14 coincidencias) · ClassName="Image" (63) ★ #1 [Alta] (única ✓) Índice determinístico sobre AutomationId (#1 de 14) By.xpath("(//Image[@AutomationId='btnImage'])[1]") alt (API, 0-based): driver.findElements(By.id("btnImage")).get(0); #4 [Baja] (63 coincidencias, #38) By.className("Image") ⚠ demasiadas coincidencias — usa el índice determinístico
  • R1Nunca el título de ventana como Name del control — en WPF sería el mismo para todos.
  • R2AutomationId numérico → se degrada (autogenerado) y se prefiere Name.
  • R3Promoción → si clicas el texto dentro de un botón, sube al control accionable.
  • R4Unicidad + índice → se indexa sobre el atributo con menos coincidencias (AutomationId › Name › ClassName).
  • R5Dos formas → XPath [n] (1-based) y findElements().get(i) (0-based).

Exploración

Árbol de objetos y resaltado en pantalla

Además de la captura por clic, un explorador jerárquico de la ventana con carga perezosa deja navegar toda la interfaz y elegir el control con precisión — sin depender del pixel exacto. Al seleccionar cualquier nodo, se dibuja un rectángulo sobre el elemento real, como Inspect.exe, mediante una ventana transparente que no roba el foco ni intercepta clics.
